**[Test Coverage for Break and Continue in Codegen]
**Learning:** Adding test coverage for basic control flow statements like `Break` and `Continue` in the codegen module is an easy win and prevents regressions. Also learned that `havoc` tests spawning subprocesses that crash with stack overflows are intentional chaos tests and should not be subverted with early panics or mitigations in code generation logic.
**Action:** Always write targeted, isolated unit tests for unexercised enum variants instead of altering existing chaos tests, and remember that codegen should assume AST validity rather than validating it.
